STAŁY PODPIS APK — JEDNORAZOWE USTAWIENIE
Dotychczasowy workflow budował debug APK bez własnego stałego klucza.
Nowy workflow buduje release, wymaga klucza w GitHub Actions Secrets i
sprawdza certyfikat podpisu oraz identyfikator pakietu przed publikacją.
Bez sekretów zatrzymuje się, zamiast wydawać APK z przypadkowym podpisem.

1. Na komputerze zainstaluj Python 3, Java (keytool) i GitHub CLI (gh).
2. Zaloguj GitHub CLI: gh auth login
3. Z folderu projektu uruchom: python tools/setup_signing.py
   Skrypt tworzy klucz tylko raz, zapisuje go w prywatnym folderze użytkownika
   SRG-signing-backup i przesyła 3 sekrety do projekt-debica-omsi2/srg.
   Jeśli wszystkie sekrety już istnieją, nie nadpisuje ich.
4. Zachowaj prywatną kopię całego folderu SRG-signing-backup (klucz i hasło).
   Nie dodawaj tego folderu do GitHuba ani do paczki ze źródłami.
5. Wgraj źródła projektu i uruchom ponownie workflow Build SRG Mobile APK.

Nie zmieniaj applicationId pl.srgmobile.classic.lcd23, klucza ani sekretów
przy następnych wydaniach. Zwiększaj versionCode każdej nowszej wersji.
Wydania ze wspólnym podpisem mogą aktualizować wcześniejsze wydania z tym
podpisem, także z pominięciem kilku wersji. Nie cofaj versionCode.
Obecna 1.4.64 może wymagać jednorazowego odinstalowania, jeśli jej podpis jest
inny. Jej klucza nie odzyskano; nie obiecujemy zgodnej aktualizacji 1.4.64.
Odinstalowanie usuwa dane aplikacji: wcześniej zapisz własne linie i ustawienia
oraz zachowaj pliki reklam/nagrań/rozkładów. Najpierw pobierz nowe gotowe APK.
